# Optional local MCP inspections

ARRS needs typed preparation and evidence inspection for a fresh agent while retaining one shared validation and policy implementation. The optional adapter lives in workflows and calls core preparation, explanation/history, doctor and audit directly. Ordinary CLI startup dynamically imports it only for `mcp --stdio`. There is no network listener, model account, shell wrapper, write tool or execution tool.

Pin `@modelcontextprotocol/sdk` to 1.32.1 for official negotiation, framing, request schemas and a real client conformance test. The tested client is that SDK's Node stdio client with MCP `2025-11-25`. The issue's linked [2026-07-28 tools specification](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) informs typed tools and structured result/error design, but its newer stateless metadata/result protocol is outside this SDK's current support. We claim the tested version explicitly. HTTP/auth packages are transitive SDK distribution costs; only stdio server/client modules are used. Existing offline CLI and skills require no server or account.

Each result uses version `0.1`, kind `mcp-inspection`, with a strict envelope schema and unchanged shared semantic data. Strict tool schemas reject unknown arguments; tool arguments cannot select a root, baseline, output or executable. The launching user pins one safe repository and optionally a retained independent baseline. Technical success, pending review, accepted implementation, blocked inspection and transport errors remain distinct. Adapter status `ok` means a completed inspection, not an additional capability or admission grant. Read-only audit preserves unevaluated execution controls.

Pages carry a structured header plus indexed items identified by JSON Pointer. Arrays become `collectionItems` markers and long strings become `stringFragments` markers; all values remain available in stable order. Random in-memory continuation handles bind selector arguments, page size, canonical repository, source and freshly recomputed result identity. Five-minute expiry, relevant drift, mismatched selectors and unknown handles reject with recovery instructions. A successful continuation consumes its prior cursor and transfers one active chain slot to its successor; errors preserve the prior cursor for retry until its original expiry. Async inspections recheck the exact incoming handle immediately before transfer, so concurrent consumers produce one successor and a structured consumed/expired error rather than exceeding capacity. Reusing a consumed cursor or losing a successful response requires a fresh inspection. Handles retain only arguments/identities/offsets, never cached documents or logs. The conservative whole-source inventory is bounded at 4096 files, 8 MiB per file and 64 MiB total; it excludes only root metadata/evidence/dependencies. This identity protects freshness and does not assert complete task scope.

Requests are bounded at 64 KiB. Structured pages are bounded at 128 KiB and 50 items; excessive mandatory data fails explicitly rather than truncating. The adapter allows 60 calls per minute and 128 active handles. Default preparation omits document/source content; explicit `includeContext` returns the shared bounded untrusted context. Raw proof logs are never returned. Command argv, paths and metadata may still be private. There is no telemetry or upload; users must inspect data before sharing with a client/model. The process retains continuation metadata for five minutes or until shutdown.

Conformance uses the actual SDK client and public CLI, configured executable sentinels, filesystem snapshots, a network-call trap, hostile repository instructions, malformed/oversized frames, current/stale proof, root/path/flag rejection, reconstructable Unicode pagination, expired/mismatched handles, shutdown and a packed installed consumer. The new standalone `mcp` verification target is staged for review; its suite is also imported by the original `operations` target. Protected proof retains all existing baseline-bound argv and exercises the new suite through that unchanged target, without re-pinning the pre-edit baseline or weakening command binding.

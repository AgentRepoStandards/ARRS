# Local proof explanations and private reviewer exports

Status: implemented; requires independent implementation review and human acceptance of the selected proof under current R3 policy.

Reviewers need the selected attempt's acceptance links, ordered scenarios, required checks, scope freshness and remaining review requirements without reconstructing captured JSON. They also need failed and interrupted attempts to remain visible. Rendering evidence must not add another admission authority or transfer acceptance between attempts.

Core exports `explainProof` and `proofHistory` as versioned `0.1` diagnostic projections, described by `proof-explanation` and `proof-history` schemas. Canonical shared technical and accepted validators remain authoritative. A technically successful proof awaiting implementation review is `ready-for-review` and unaccepted. Invalid attachments are reported separately even when another attachment validates. The schemas describe outputs, not a substitute input for proof/work/audit admission. Consumers must select this version and may not interpret partial parsing as success.

History indexes immediate canonical attempt directories with bounded non-following reads (1 MiB JSON, 20 MiB logs, 2000 entries). An oversized attachment leaves shared technical status intact but prevents the observer from establishing acceptance; the report exposes its observer limit and skips an unbounded aggregate re-read. Authoritative admission rules remain unchanged. It preserves baseline sessions, failed manifests, interrupted allocation markers, stable paths and individual diagnostics. Explicit selection appears first; current accepted evidence precedes older invalid records. Session provenance supplies an untrusted grouping hint and never authorizes a read outside evidence or changes acceptance. Audit condenses more than three historical warnings into a count and retains the exact authoritative-validator diagnostics in `proofHistoryWarnings` JSON. Its accepted-evidence test remains unchanged.

Canonical UUID capture directories retaining only partial step logs remain visible as interrupted entries without reading the logs or authenticating execution. Selection applies to manifests, baseline sessions, allocation markers and partial-log directories; history never invents missing markers or promotes those records into proof.

Exports are explicit exclusive local artifacts strictly beneath ignored `.arrs/reports/`, outside configured canonical evidence. Safe repository paths reject traversal and symlinks. Export checks all supplied input and output before artifact writes. Static HTML escapes every evidence field, replaces nonprinting controls, uses only local CSS and contained anchors/files, and sets a restrictive Content Security Policy. It uses no script, web framework, asset request, upload or telemetry.

Raw logs are omitted by default. Argument vectors, criteria, scope names and review notes remain useful metadata and may themselves contain private values; omitting logs is not a privacy guarantee. Explicit `--excerpts` verifies original byte hashes, bounds each excerpt to 8192 UTF-8 bytes and limits exports to 100 results. Heuristic redaction is the default; `--redaction none` explicitly preserves excerpt text. Redaction happens before truncation, is labelled, and cannot certify absence of secrets. Original digests and exported excerpt digests are separately labelled. The artifact is a preview for maintainer inspection before any decision to share; this workflow performs no sharing action.

Legacy manifests retain declared-scope limitations. When changeset evidence is available, only the existing successful shared proof validator can establish its recorded coverage; a fresh unrelated inspection cannot upgrade an old manifest. Unavailable selected protected baseline context blocks technical/accepted claims. All reports remain local assertions rather than authenticated execution, lineage or reviewer identity.

# Explicit Git changesets and opt-in proof coverage

Status: accepted for implementation; completed implementation acceptance remains a separate human decision.

The existing v0.1 proof establishes freshness of declared source, not discovery of all changes. Keep that meaning. An optional `changeset: {version: "1", mode: "git", base: "<revision>"}` capability requests complete Git coverage and requires recapture. A captured manifest adds `changesetSnapshot`; older CLIs reject these new fields. Manual inspection remains `declared-only` and cannot satisfy this capability.

`scope inspect --base <revision>` and `scope check <plan> --base <revision>` inspect an explicit local commit without fetching or executing project commands. The base is distinct from independently selected trusted policy context. Supported Git is 2.52.x, the bounded implementation's qualified version. Unknown versions fail explicitly. Git runs with a fixed argument prefix and stripped Git environment, disabled system/global configuration, fsmonitor, optional writes, replacement objects, external diff, textconv, lazy fetching and all transport protocols.

Inventory preserves committed base-to-HEAD, staged HEAD-to-index, unstaged index-to-raw-filesystem and nonignored untracked layers. Committed/staged rename similarity is diagnostic; both paths enter coverage even without rename detection. Raw filesystem bytes are compared directly to indexed blob identities without invoking clean filters, so line-ending conversion may appear as a change. Both endpoints remain visible even when intermediate changes cancel. Aggregate endpoints retain base blob/mode and current SHA-256 or explicit absence. Submodules, symlinks, unmerged/sparse index states, missing objects, unsafe paths and exceeded limits cannot produce complete coverage.

Two complete collections must agree on base resolution, HEAD, repository/worktree identity, index/shared-index bytes, layers and the bounded raw-byte working inventory. No result is emitted as complete after concurrent drift. Later validation repeats collection and compares the whole snapshot; a HEAD/index/untracked/working change invalidates evidence. Exact root `.git`, `.arrs` and `node_modules` are explicitly excluded source domains, including filesystem-identical aliases. Tracked excluded changes remain listed as excluded, never covered. Nested directories with those names remain source.

An absent declared file qualifies only when the captured complete inventory proves a regular base blob and present-to-absent aggregate endpoint for that exact path. Its scope freshness digest is SHA-256 of a versioned, domain-separated absence record containing base commit, path and former object/mode. Directory scopes retain existing hashing; deletion provenance lives in the snapshot. Unbound/legacy proof cannot hash a missing file or acquire Git coverage from a later inspection.

Coverage uses normalized safe paths and existing filesystem alias rules. Current controls and historical base maps/policy supply maximum diagnostic floors and mapped verification obligations, including removed paths. Historical facts never grant policy-transition trust; protected admission still requires independently supplied pre-change context and retains existing gates. Local snapshots and hashes are integrity evidence, not authenticated hostile-author attestation.

Bounds: 30,000 entries, 64 MiB per file/object, 256 MiB total source inventory, 16 MiB per Git output and 10 seconds per Git call. A failure is incomplete or unsupported with diagnostics. Read-only mode does not create caches, evidence or work records and never updates the index.

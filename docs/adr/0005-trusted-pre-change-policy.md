# Select a pre-change policy independently of the candidate

Status: selected for issue #28 implementation; independent implementation review and human acceptance remain required.

The candidate checkout can redirect its risk-policy pointer or weaken its own rules. Candidate-only classification cannot authorize that transition. Introduce an optional, explicit baseline context rather than a universal filename risk floor.

A human or trusted workflow selects a known-good external repository directory before editing, validates it with `arrs baseline inspect <directory>`, and retains its absolute directory and returned SHA-256 independently of candidate-authored configuration and plans. The digest covers the selected configuration, risk policy, architecture policy and scanned Feature Map JSON inventory, including their relative names and bytes. It additionally pins the sorted non-following filesystem identity inventory (relative path, file/directory type, device and inode) of the selected source, including generated source. The exact root `.git`, `.arrs` and `node_modules` trees are excluded before inspecting entries. Source traversal is bounded and rejects symlinks. This preserves the source identity relationships used by alias floors: a same-byte hardlink replacement cannot silently lower risk. The source must remain available and unchanged; baseline directories equal to or inside the candidate are rejected. This supports non-Git repositories and custom configured policy/map locations. The configuration filename remains the existing `arrs.json` contract. No Git base is inferred.

Every protected command supplies `--baseline <directory> --baseline-sha256 <digest>`. Proof/session/manifest, work and generated review records persist the same `policyBaseline` reference. A reference alone cannot establish trust: validators require independently supplied matching context. Missing, invalid, mismatched or changed baseline state fails; it never downgrades to candidate-only admission. A digest binds selected control bytes and measured source identities, without authenticating identity or history or attesting source contents. Prepare/build the source before selection and retain it immutably; conservative replacement/rebuild drift requires restoring the original source. The traversal includes at most 30,000 directories/files. A snapshot first selected from the candidate after its edit does not satisfy this workflow. Local metadata cannot authenticate pre-change timing, reviewer identity or an author replacing the trusted implementation and workflow.

Protected classification retains the maximum requested, baseline and candidate scope floors, using normalized and filesystem-identical paths in both sources. At the resulting declared risk, applicable baseline and candidate class requirements combine: checks are a union, review and human approval are disjunctions, autonomy takes the stronger setting, and runtime verification takes the earlier threshold. Proof-required checks from both configurations remain required. Baseline and candidate bindings for each required command, behavioral step and applicable Feature Map target must retain identical argv and timeout. Binding drift rejects before execution or allocation. Supported policy transitions can change pointers, sensitive rules and class gates while retaining command mappings; command changes require a separately reviewed staged transition and a newly selected known-good baseline. This bounded interface does not execute two command variants.

Technical and accepted validation, review attachment, proof run/start/finish, work readiness/completion and audit share the context. Immutable attempts and reviews retain their existing lifecycle; a supplied baseline never substitutes for execution authorization, independent implementation review or human acceptance.

Compatibility: absent context and absent persisted reference retain existing candidate-only local behavior, explicitly labeled informational/unprotected in CLI and audit results. Such proof may establish local technical readiness under current policy, but it cannot establish that a governing policy transition was authorized. Optional v0.1 fields require the corrected CLI; older CLIs reject unknown fields. No dependency, mandatory consumer path, complete changed-file discovery or signed attestation is introduced.

The protected source domain excludes normalized root `.git`, `.arrs` and `node_modules` floor references (sensitive paths and Feature Map implementation/entry points) and scope/work-context queries, including filesystem-identical case aliases. These identity operands are outside the pinned source inventory and reject with an actionable diagnostic. Ancestor `.` remains supported for risk/audit, as do nested reserved-name source directories and distinct uppercase source on case-sensitive filesystems. Candidate-only consumers retain their prior behavior. Trust flags select exactly one root/digest pair; duplicate `--baseline` or `--baseline-sha256` options reject before effects rather than silently choosing the last value.

# Product and domain

ARRS serves maintainers and coding agents who need useful engineering work to survive context loss and changing orchestration tools. Its unit of adoption is a repository. The CLI initializes a durable contract, assesses its capability and records verification evidence locally.

A maintainer owns the product goals, risk policy, acceptance quality and permitted autonomy. An implementing agent owns a bounded change and its proof package. A reviewer assesses the change independently where policy requires it. The Gardener improves recurring failure prevention. These roles can share tooling; required independent review remains a distinct review of the implementation.

The [glossary](../../GLOSSARY.md) defines canonical terms. [Feature Maps](../feature-maps.md) connect these product capabilities to their implementation. A repository can use ARRS without any specific agent vendor, issue tracker or remote service.

# Local capability graph

`arrs impact src/domain/file.ts --json` reports every overlapping maintained Feature Map, maximum scope risk and all configured verification obligations. `arrs impact --base <local-commit> --json` uses the explicit complete Git inventory to retain committed, staged, unstaged, untracked, deleted and renamed endpoints, unmapped source, and comparison-side risk and target obligations. The named Git base supplies comparison facts; an independently retained `--baseline` and digest still supply protected policy context.

`arrs context feature <id> --json` returns maintained goal, owners, boundaries, source references, invariants, acceptance strings, configured argv, declared dependencies, related decisions and explicitly related work. `arrs context drift --base <local-commit> --json` compares exact map statements and target bindings with before/after source path, digest, pointer and revision. Code changes do not certify semantic prose freshness. Runtime reachability, dynamic/computed imports and semantic test quality remain analysis gaps.

Every node and relationship has explicit provenance. `maintained` relationships come from map/config/work fields; `observed` relationships come from the selected canonical proof and shared current validators. Candidate relationships never grant readiness. Feature membership and exact criterion text must both match a concrete work item. Its exact selected attempt must satisfy scoped readiness before graph evidence can qualify. Unrelated technically valid proof, missing, failed, stale, invalid, current technical and accepted evidence remain distinguishable. Existing proofs retain their declared-only assurance; running an impact query does not upgrade historical capture to complete Git coverage. Repository admission gates and actual human acceptance remain separate.

The `capability-graph` result uses additive schema version `1`; existing Feature Maps stay v0.1. Because v0.1 invariant and acceptance statements are strings, their identity is feature ID plus exact text. Reordering retains node identity; changing text changes it. This is textual identity, not an invented stable semantic ID. See [the provenance decision](adr/0008-capability-graph-provenance.md).

Default commands only read local inputs. They execute no configured command, language adapter runtime or network operation and write no report, cache, evidence or work state. Explicit `--base` invokes only the qualified read-only Git adapter. Configured feature/work/decision locations are respected; unsupported work providers, unsafe paths, symlinks, unknown contract versions, duplicate identities, malformed files and dependency cycles return an incomplete result and nonzero CLI exit. Incomplete collection withholds every graph criterion qualifier and current-evidence edge; raw canonical proof facts remain observations, and no paging cursor grants partial success.

JSON, terminal and `--html` output consume the same result. HTML is static, escaped and has a restrictive content security policy; redirect stdout to an ignored local path to retain it. No local server or network asset is required. `--json` and `--html` are mutually exclusive.

Use `--limit 1..1000` (default 200) and `--cursor <returned-token>` to page nodes. The cursor binds the exact inputs/query identity and rejects drift. Edges use full stable IDs and remain complete in each page; a page intentionally may reference nodes on another page. The result states total nodes and collection bounds: 2,000 maps, 64 work items, 20,000 nodes, 50,000 edges, 20,000 criterion evidence records, 20,000 drift records, 16 MiB collected output records, 1 MiB per metadata file and 64 MiB total metadata (including historical contract bounds). Shared readiness separately bounds its metadata and evidence readers; exceeding those limits prevents qualification. No incremental-cache claim is made. The synthetic 200-feature test prints measured generation duration, page bytes, node and edge counts (initial local measurement: 404 ms, 607 nodes, 1,601 edges and 885,426 bytes for a 25-node page with full edges); the measurements cover maintained local facts without selected work evidence.

`./repo verify graph` executes the configured graph fixture suite. The standard verify command also witnesses these cases without changing existing argv bindings. Adding this target does not repin or weaken the independently retained baseline; the target mapping remains part of the final human implementation review.

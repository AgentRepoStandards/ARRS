# First external adoption qualification

Scope: historical development qualification of Q01–Q07 on 2026-10-07, using the development checkout's CLI and isolated synthetic repositories. This report summarizes the findings and local results from that qualification; it does not establish current public-snapshot verification. No application repository, global installation, upstream revision, remote publication or deployment was changed by the qualification work.

Risk: R3 because the qualification changed schemas and public qualification/security contracts. Original tracked execution plans, proof metadata and review records remain in the private development repository and are excluded under the [public snapshot policy](../public-snapshot-policy.md). Historical ignored logs and generated evidence are not distributed, and their availability has not been established by this preparation. The reported historical results below have not been independently reverified for this snapshot and do not establish external approval or acceptance of it. Reproduce the relevant scenarios and capture new evidence when validating a current checkout.

## Findings and dispositions

**Q01 — Confirmed setup/diagnostic implementation defect; high priority; fixed.** Hypothesis: init emits an immediately schema-invalid architecture policy. Reproduction confirmed `modules: []` against `minItems: 1`; doctor and both audit controls repeated malformed-policy errors. Specification sections 3/5 require honest setup and real enforced boundaries. Sources: [init](../../src/workflows/init.ts), [schema](../../schemas/architecture.schema.json), [scanner](../../src/core/architecture.ts). Decision: accept the existing empty scaffold as valid unconfigured setup, then reject architectural capability in both scanner entry points. Neither dummy modules nor inferred boundaries are added. [CLI regressions](../../tests/cli.test.mjs) cover coherent initialization, missing guidance, malformed policies, no promotion, byte preservation, dry run/idempotency and real forbidden imports. Before evidence: `.arrs/qualification/Q01-before.log` and `Q01-regression-before.log`; after: `Q01-Q03-bootstrap-final.log` and `Q01-guards-final.log`.

**Q02 — Original conflation diagnosis incorrect; diagnostic/design limitation; medium priority; bounded correction delivered.** Dependencies are already non-expiring `{name, reason}` records in a separate `dependencies` array; scoped policy exceptions have expiry/approver fields. Init approves neither existing nor new packages. Specification section 5 intentionally makes unjustified dependencies visible. Source: [security](../../src/core/security.ts), [exceptions schema](../../schemas/exceptions.schema.json). Improved diagnostics direct maintainers to the rationale array and distinguish inventory from approval/waiver. Enforcement remains intact. [Regression](../../tests/diagnostics.test.mjs) proves an invented or rewritten inventory grants no approval and unknown baseline fields fail validation. Existing core coverage still rejects missing rationale and invalid/expired waivers. Version/source/lockfile approval is not bound by the current name-only model; secure change-aware baselining is deferred because it needs trusted comparison/review protection. No upgrade is automatically classified low risk and no dependency was added.

**Q03 — Hard-coded audit diagnosis incorrect; initializer discovery and CI false-positive defects confirmed; high priority; fixed within bounded support.** `ci.workflow` was already configurable, and an alternative explicit path passed before this patch. Init defaulted to one filename without discovery. The former textual scan accepted folded scalars, run-looking metadata, ignored failures through expressions, reusable workflows and an `echo` audit script containing flags. Specification section 8 requires actual gate invocation without claiming hosted success. Sources: [CI inspector](../../src/core/ci.ts), init, audit and doctor. New-config discovery selects a sole file or unique supported candidate; existing config is preserved. Inspection reads bounded GitHub jobs/steps and unconditional direct commands, rejecting unsupported forms and failure suppression. Independent review additionally reproduced invalid npm/CLI invocation forms and unsupported audit flags, shell function shadowing, invalid trigger scalars and unestablished multicommand failure propagation; regression coverage addresses them. [CI tests](../../tests/ci.test.mjs) cover positive/negative forms, renamed files, comments, conditions, reusable workflows, ambiguity and presence without promotion. Before: `Q03-before.log`, `Q03-red.log`, `Q03-init-before.log`; review: `independent-ci-audit-review.json`. Remote run, required checks, branch protection and arbitrary action semantics remain unobserved.

**Q04 — Confirmed diagnostic implementation defects; high priority; fixed.** Doctor's AGENTS claim checked only existence, although its detail said navigation contract. Audit represented unauthorized execution and unconfigured prerequisites as undifferentiated failures. Specification sections 3/8 require accurate diagnostic claims and fail-closed maturity. Sources: [doctor](../../src/core/doctor.ts), [audit](../../src/core/audit.ts), [types](../../src/core/types.ts), [CLI](../../src/cli.ts). Doctor now labels instruction/CI file presence; output retains `passed` and adds deliberate diagnostic states plus optional audit prerequisites. Dependent guard/classification checks are blocked instead of repeating invalid-policy failures. Read-only commands remain unexecuted; explicit failures retain exit status. [Diagnostics tests](../../tests/diagnostics.test.mjs) include sentinel command nonexecution, missing commands, one authorization diagnostic, code 37 and doctor/audit agreement on broken references. Before: `Q04-Q06-before.log` and the formal proof session's before log. Final before/after uses the same configured qualification target.

**Q05 — Context rigidity and product-placeholder false positive confirmed; high priority; fixed with disclosed heuristics.** Literal keyword/path matching rejected concise equivalent rules and scoped navigation while accepting broken links. The reported product PASS did not by itself establish a defect; controlled init reproduced one. A trailing word boundary after `Configuration requirement:` prevented matching the generated marker. Initial source inspection predicted rejection; the reproduction disproved that explanation. Specification sections 1/3/8 require discoverable concise context without fabrication. Sources: [shared context assessment](../../src/core/context.ts), [substance predicate](../../src/core/files.ts). Bounded local navigation validates resolvable configured references and recognizes alternative wording; root budgets remain. The marker regex is corrected. [Context tests](../../tests/context.test.mjs) cover alternatives, broken/absolute references, configured paths, placeholders, substantive preserved knowledge and ordinary inline code. Independent review caught slash-containing code mistakenly treated as a filesystem path; this received regression protection. Before: `Q05-before.log`; after: `Q05-after.log`. Static checks still cannot prove semantic freshness or adequacy for every task.

**Q06 — Original contradiction diagnosis incorrect; vacuous engine qualification gap confirmed; medium priority; fixed.** Risk coverage and engine floors are different claims. Empty coverage already failed `risk`, preventing Level 4, but the classifier loop over zero rules still passed without exercising a floor. Specification sections 7/8 require actual sensitive rules and effective classification. Source: audit and existing risk/config classification. Empty coverage now reports incomplete and blocks classifier assessment; invalid maps also block effective classification. The successful claim names exercised declared rules and disclaims coverage adequacy. Diagnostics regression verifies empty rules cannot pass classification or silently qualify. Existing normalized-scope/parent-path and R3/R4 negative tests remain. No fabricated sensitive paths, weakened floors or unauthenticated not-applicable mechanism were added.

**Q07 — Skills location hypothesis incorrect; local work-path design limitation confirmed; medium priority; corrected.** `skills.path` already controls installation/assessment and preserves local edits. Work audit alone fixed the reference directory to `.agent/work-items`; v0.1 intentionally supports local structured work, not remote trackers. Specification sections 9/10 require self-contained readiness and proof-aware transitions. Sources: [work provider](../../src/core/work-provider.ts), [work workflow](../../src/workflows/work.ts), config/schema/types. Optional local provider/path configuration defaults to the existing directory. Unsupported providers fail audit and work operations; no named external provider can pass on assertion alone. [Workflow regressions](../../tests/workflows.test.mjs) cover relocated items, unsafe/generated paths, missing/unsupported providers and alternate skills installation/conflict preservation. Original source-only work-location reproduction used the HEAD audit transplanted into an ignored test harness with the new path supplied; it is explicitly not an untouched end-to-end baseline. Before: `Q07-before.log`; after: `Q07-after.log`. No pretend items or reviewer records were created to improve the self-audit.

## Compatibility and delivered components

Schema/config/report contract remains `0.1`; package release identifier remains `0.1.0` and nothing is published. Architecture accepts the empty setup array additively while rejecting incomplete capability. Optional `work` is additive and defaults to previous behavior; older CLIs reject that property, so use the corrected checkout-built CLI when enabling it. Shared bounded assessment modules avoid duplicated doctor/audit rules. No dependency additions, dynamic adapter ABI, tracker integrations or general CI parser were introduced. [Adoption guidance](../adoption.md), [specification](../spec/0.1.md), relevant Feature Maps and Gardener guidance match the behavior. Pack `0.1.1` updates only adoption/Gardener adaptations and hashes; Matt Pocock's pinned revision, pristine sources, licenses and attribution are unchanged. Installation preserves existing local adaptations.
